# attendance-2 가이드 (STEP 2 — 2일차 프로젝트)

`attendance-1`을 복사한 뒤, 2일차에 배운 클래스/객체/생성자/상속/인터페이스/컬렉션을 적용해 배열 기반 코드를 객체지향 구조로 리팩터링한 프로젝트입니다.

## 1일차 → 2일차 변경 사항

| 1일차(attendance-1) | 2일차(attendance-2) |
|---|---|
| `String[] names`, `String[] statuses` 배열 | `Person`을 상속받는 `Student` 객체 + `List<Student>` |
| 상태 판단 로직이 `App`의 static 메소드 안에 있음 | `Attendable` 인터페이스 규격에 따라 `Student`가 직접 `checkIn`/`checkOut` 구현 |
| 별도의 이력 저장 없음 | `Attendance` 객체로 한 건씩 기록, `Map<String, List<Attendance>>`로 학생별 이력 관리 |
| 배열 순회로 이름 검색 | `ArrayList`(`students`)를 `for-each`로 순회하며 검색 |

## 새로 추가된 클래스

- [Person.java](src/Person.java) — 이름을 갖는 부모 클래스
- [Student.java](src/Student.java) — `Person`을 상속(`extends`)하고 `Attendable`을 구현(`implements`), 출석 상태 판단 로직 포함
- [Attendable.java](src/Attendable.java) — `checkIn`, `checkOut`, `getStatus` 규격을 정의하는 인터페이스
- [Attendance.java](src/Attendance.java) — 출결 기록 한 건(학생명/상태/시각)을 표현하는 객체
- [App.java](src/App.java) — 메뉴 처리 및 `ArrayList`/`Map`을 이용한 명부·이력 관리

## 단계별 작업 순서

1. **Person, Student 설계** — 공통 필드(`name`)는 `Person`에 두고, `Student`가 이를 상속받아 출결 관련 필드/메소드를 추가합니다.
2. **Attendable 인터페이스 도입** — 출석 처리 기능(`checkIn`, `checkOut`, `getStatus`)을 인터페이스로 규격화하고 `Student`가 구현하도록 합니다.
3. **Attendance 객체로 이력 관리** — 출석/조퇴가 발생할 때마다 `Attendance` 객체를 만들어 `Map<String, List<Attendance>>`에 누적 저장합니다.
4. **ArrayList로 명부 관리** — 배열 대신 `List<Student>`를 사용해 학생을 등록·검색합니다.
5. **메뉴 재구성** — "학생 등록" 메뉴를 추가하고, 기존 출석/조퇴/전체보기 메뉴에 "학생별 출결 이력 보기"를 추가합니다.

## 실행 방법

1. `src/App.java`를 열고 Run으로 실행합니다.
2. 먼저 1번(학생 등록)으로 학생을 등록한 뒤 출석/조퇴 체크를 진행합니다.
3. 5번으로 학생별 출결 이력이 누적되는지 확인합니다.
